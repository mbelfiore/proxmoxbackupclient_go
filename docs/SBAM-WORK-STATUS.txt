LAVORO ESEGUITO:
- Sostituito il fragile errch per-worker con context condiviso, first-error protetto e WaitGroup.
- Ogni worker produce un solo esito implicito; eliminato il doppio invio errore/nil.
- Il primo errore critico cancella producer, dispatcher incorporato e lavoro non ancora iniziato.
- uploadWorker attende producer e tutti gli otto worker prima di ritornare; ciò garantisce assenza di goroutine superstiti dopo il return, ma può ritardare il return se una I/O sottostante non è cancellabile.
- Assignment e CloseFixedIndex non vengono eseguiti dopo errore, panic producer, cancellazione o overrun.
- Introdotta blockProducer con emit cancellation-aware e proprietà chiara del channel jobs.
- Errori di lettura producer vengono restituiti; panic producer sintetici vengono convertiti in errori.
- File producer e PhysicalDrive reader vengono chiusi su cancellazione per interrompere letture dove supportato dall'OS.
- Refactor producer Windows conserva raw gaps, VSS, padding, chunk 4 MiB e short final chunk.
- Copiati i blocchi emessi dal buffer Windows per evitare mutazioni concorrenti dell'array sottostante.
- Preservati digest/checksum ordinato, assignment fuori ordine, dedup e zero-block optimization.
- Nessuna modifica a statistiche, VSS policy, mount mapping, P2V, NBD, GUI o telemetry.
- Le sole API FIDX usate da machinebackup hanno ora varianti context-aware; i wrapper storici restano compatibili usando context.Background.
- Create/upload/assign/close e download dell'indice precedente costruiscono request con NewRequestWithContext.
- La cancellation della pipeline interrompe una richiesta fixed-chunk in-flight, verificata sia al server httptest sia dal workflow uploadWorker.
- Il PhysicalDrive e il file snapshot VSS attualmente letti ricevono un close hook legato al context; ownership e chiusura normale restano nel producer.
- Il TLS dial iniziale usa ora tls.Dialer.DialContext, senza timeout globale del client.
- L'upgrade HTTP/1.1 verso il protocollo PBS è isolato in una funzione context-aware: cancellation chiude soltanto la connessione posseduta, sblocca write/read, preserva context.Canceled e chiude anche sui server error.
- CancelIoEx NON è stato applicato cosmeticamente: le sorgenti sono aperte con os.Open e il percorso Go corrente usa handle/file I/O sincroni; CancelIoEx è definito per pending asynchronous I/O e os.File.Fd non è sicuro durante I/O concorrente. La Close già presente resta la misura prudente.
- La risposta upgrade accetta soltanto una status line HTTP riconoscibile con codice numerico esattamente 101; risposte vuote, troncate, malformate o non-101 falliscono chiuse.
- La risposta header upgrade è limitata a 64 KiB senza bufferizzare oltre il terminatore e senza leggere byte del successivo protocollo HTTP/2.
- Una write parziale della richiesta upgrade restituisce io.ErrShortWrite e non avvia la lettura della risposta.
